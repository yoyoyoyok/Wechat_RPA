# 公众号文章链接采集工具（collector_webapp）

基于 [pywechat](../README.md) 项目的 `pyweixin`（微信 4.1+ UI 自动化）能力构建的本地 Web 控制台，
用于批量搜集、整理特定微信公众号的历史文章链接。

---

## 一、背景

- **上游项目**：pywechat 是开源的 Windows PC 微信自动化库（pywinauto / UI Automation，无 Hook）。
  `src/pyweixin` 面向微信 4.1+，本机已验证微信 **4.1.13.65** 可用。
- **已有能力**：`Collections.collect_offAcc_articles`（进入公众号主页批量右键收藏文章）与
  `Collections.cardLink_to_url`（在收藏界面逐条复制卡片链接 URL）——但两者均为同步阻塞循环，
  内部无暂停检查点，且部分定位逻辑不适配 4.1.13.65（详见第四节）。
- **需求**：本地 Web 界面，对特定公众号做文章链接的整理搜集；采集期间 RPA 占用鼠标键盘，
  因此必须有**随时暂停**的手段（全局热键）和网页按钮。
- **约束**：**不修改 pywechat 源码**（开源项目后期会更新），采集循环在应用侧自行重写。

## 二、目标

| 目标 | 说明 |
|---|---|
| 多公众号任务队列 | 每个任务 = 公众号名称 + 目标篇数，排队依次执行 |
| 全自动两阶段采集 | 阶段1：进入公众号主页逐篇右键"收藏"；阶段2：打开收藏界面逐条复制链接 URL |
| 本地持久化 | SQLite（`collector.db`）：任务表 + 文章表（URL 唯一约束去重） |
| 暂停/停止双通道 | 全局热键 `Ctrl+Alt+P` 暂停/继续、`Ctrl+Alt+S` 停止当前任务（微信占用鼠标时可用）；网页同功能按钮，浏览器聚焦时按空格也可切换暂停 |
| 停止语义 | 停止 = 结束当前任务、保留已采集数据、队列挂起，需手动点"继续"恢复 |
| 实时可视 | 页面轮询显示：当前任务阶段与进度、运行日志、任务队列、已采集链接列表（按公众号筛选） |

技术栈：FastAPI + uvicorn + 原生 HTML/JS 单页（无构建步骤）+ SQLite + `keyboard`（全局热键）+ `pyautogui`（滚轮）。

## 三、架构与文件

```
collector_webapp/
├── app.py            # FastAPI 入口：静态页 + REST API + 全局热键注册
├── engine.py         # 采集引擎：worker 线程 + 可暂停/停止的两阶段循环（核心）
├── store.py          # SQLite 存储（任务/文章两表，URL 去重）
├── static/index.html # 控制台单页
└── collector.db      # 运行时生成
```

- **engine.py**：`Control.checkpoint()` 在每篇文章/每条链接处理前检查信号——暂停则阻塞等待，
  停止则抛 `TaskStopped`；worker 线程需 `pythoncom.CoInitialize()`（pywinauto COM 线程要求）。
- **API**：任务队列、公众号清单 `/api/accounts`、批量任务 `/api/tasks/batch`、文章删除/导出 `/api/articles` 与 `/api/articles/export`，以及暂停/继续/停止控制接口。
- **启动**：`cd collector_webapp && python app.py` → 打开 http://127.0.0.1:8765

## 四、微信 4.1.13.65 兼容性发现（重要，排障结论）

原 `pyweixin` 流程在本版本失败，逐项实测后的结论：

1. **公众号主页窗口变了**：不再是标题"公众号"的 Pane（`Panes.OfficialAccountPane` 找不到，
   这是首次失败的直接原因），而是打开在**微信内置浏览器窗口**（`Chrome_WidgetWin_0`，标题"微信"）内，
   内容为其下的 `Document`（标题为公众号名）。
2. **"公众号主页"按钮单击即可**；双击 = 开→关切换（原代码 double_click 会导致看起来没打开）。
3. **右键菜单**：右键**文章标题**（右键日期无效）弹出菜单，菜单项为 `ListItem`"收藏"；
   前提是浏览器窗口必须在前台，否则 `right_click_input` 的屏幕坐标点击会被遮挡窗口截走
   （表现为"菜单未出现"）。
4. **无障碍树（UIA）特性**：包含**全量文章列表**（含视口外元素，坐标在窗口视口外可据此过滤）；
   页面滚动后**约 2 秒**才刷新，循环必须等待。
5. **滚动方式**：`{DOWN}`/`{PGDN}` 键无效，须用鼠标滚轮（`pyautogui.moveTo(窗口中心)` + `scroll`，
   滚轮作用于**鼠标当前位置**）。
6. **文章卡片两种结构**（过滤器需兼容）：
   - "全部"标签：标题 / 日期 / `阅读 x 赞 y`
   - "文章"标签：标题 / `原创` / 作者 / 时间戳（如 `2026年9月18日 16:43`）/ IP 属地
   - 过滤策略：标题文本 + 坐标在视口内 + **父 Group 含"阅读"或时间戳文本**（排除公众号简介等头部文本）
7. **收藏卡片文本**：`"链接" + 文章标题 + 收藏者昵称 + 公众号名 + 时间戳`——标题还原采用
   收藏阶段记录的干净标题做**前缀匹配**，否则去掉公众号名后缀兜底。
8. **残留窗口干扰**：上次运行/调试遗留的内置浏览器窗口（含旧标签页）会让主页打开流程落错标签页，
   采集开始前需清理残留 `Chrome_WidgetWin_0` 窗口。

### 仍需真实微信环境回归

当前代码已增加诊断和明确失败判定，但 UI 自动化仍依赖登录账号、UIA 可见性以及具体微信版本。
必须在目标机器上用至少 5 篇（含滚动翻页）任务回归，确认不同窗口尺寸下的文章点击坐标和收藏菜单定位。

### 下一步计划

1. 在目标微信版本上用 ≥5 篇（含滚动翻页）任务回归验证：收藏数、URL 去重、标题清洗、暂停/停止热键。
2. 若微信版本再次变化，根据运行日志中的扫描统计调整窗口/卡片定位。
3. 长期项：提取阶段从收藏列表顶部取 N 条，若收藏里预存其他卡片链接可能被一并提取
   （URL 去重防重复，但"公众号"归属列可能标到当前任务名下）。

## 六、使用说明

1. 推荐双击项目根目录的 `start_collector_gui.bat` 快捷启动；也可使用 `cd collector_webapp && python app.py`，再打开 http://127.0.0.1:8765
2. 可在“公众号管理”维护常用公众号并勾选多个公众号连续执行，也可直接输入名称创建单个任务
3. 勾选“复制后移除收藏”时，链接成功复制入库后会自动删除对应微信收藏卡片
4. 在文章列表中可搜索、勾选删除或导出 CSV
5. 采集期间不要动鼠标键盘；需要临时接管时按 `Ctrl+Alt+P` 暂停
6. `Ctrl+Alt+S` 或网页“停止当前任务”结束当前任务（数据保留，队列挂起）
7. 停止后页面控制区会显示“继续”，点击后恢复队列；已采集链接在页面底部表格查看，可按公众号筛选
